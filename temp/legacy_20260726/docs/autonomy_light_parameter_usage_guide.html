Livox MID360/MID360s + Point-LIO 기반 로봇 중심 Height Map 런타임

기준: 현재 저장소의 config/autonomy_light.yaml · 작성일: 2026-07-26 · 단위: 별도 표기가 없으면 m / s / rad

기준값과 적용 위치
표의 기본값은 현재 YAML에서 읽었다. 설치된 Jetson에서는 /etc/cocelo/autonomy-light/autonomy_light.yaml을 수정한다. 변경값은 시작 시에만 읽으므로 프로세스를 재시작해야 한다.

1. 시스템 개요와 빠른 시작

LiDAR → Livox driver → Point-LIO → 등록 scan / 전역 정밀 지도 → height map 생성 → 외부 ROS 2 제어 출력

운용 전 확인

  1. LiDAR NIC 이름과 IP를 확인하고 livox_interface, livox_host_ip, livox_lidar_ip을 맞춘다.
  2. LiDAR 장착 자세와 target_to_lidar_xyz/rpy를 실제 base_link 기준으로 맞춘다.
  3. 수신 제어기의 ROS_DOMAIN_ID를 external_ros_domain_id와 일치시킨다.
source /opt/ros/humble/setup.bash
source ~/ros2_ws/install/setup.bash
./launch.sh --real                 # YAML의 LiDAR 모델 사용
./launch.sh --real --mid360s --vis # 모델 override + HeightMap 뷰어

# Debian 설치 환경
autonomy-light --real
autonomy-light --real --map "$HOME/autonomy-light-maps/site.pcd"
상황명령 / 옵션설명
실제 로봇--real기본 모드. Livox driver와 Point-LIO를 시작한다.
시뮬레이션--sim --sim-topic-prefix /f4driver를 시작하지 않고 시뮬레이터 LiDAR/IMU topic을 쓴다. root topic이면 prefix를 ""으로 지정한다.
노드만 점검--no-driversLivox 및 Point-LIO 없이 autonomy_light만 실행한다.
설정 파일 교체--config FILE실험용 YAML을 지정한다.
저장 지도--map FILE.pcd초기 재지역화 성공 전까지 height map 출력은 보류된다.

2. 설정 변경, 검증, 지도 생성

sudo nano /etc/cocelo/autonomy-light/autonomy_light.yaml
# 실행 터미널에서 Ctrl+C 후
autonomy-light --real

ROS_DOMAIN_ID=0 ros2 topic hz /autonomy_light/height_map_data
ROS_DOMAIN_ID=0 ros2 topic echo /autonomy_light/heartbeat --once
튜닝 원칙
한 번에 한 계열만 변경하고, 값·주행 환경·결과를 기록한다. 좌표계/장착값이 틀린 상태에서는 필터 파라미터를 바꿔도 해결되지 않는다.

저장 지도 만들기와 사용

mkdir -p "$HOME/autonomy-light-maps"
autonomy-light-mapping --real --output "$HOME/autonomy-light-maps/site.pcd"
# 경로 주행 → Ctrl+C 한 번 → pose-graph 완료 로그까지 대기
autonomy-light --real --map "$HOME/autonomy-light-maps/site.pcd"

site.pcd는 refined 지도, site.raw.pcd는 복구/진단용 원본이다. heartbeat가 ready:...가 될 때까지 저장 지도 기반 제어 입력을 사용하지 않는다.

3. 좌표계, 지도 형상, 출력 메시지

파라미터기본값용도 및 설정 기준

HeightMap 해석

외부 제어 메시지는 /autonomy_light/height_map_data, 타입은 autonomy_light/msg/HeightMap이다. 필드는 header, float32[] data, resolution, x_length, y_length다.

width  = ceil(x_length / resolution)
height = ceil(y_length / resolution)
index  = row * width + col     # row: y_min → y_max, col: x_min → x_max
x = -0.5*x_length + (col+0.5)*resolution
y = -0.5*y_length + (row+0.5)*resolution
data[index] = clipping.max_z - cell_z

현재 clipping.max_z=0.48이므로 평지는 대체로 0.48에 가깝고, 높은 장애물일수록 0.0 쪽으로 작아진다. data는 raw z가 아니라 거리형 값이다.

5. 높이 기준과 Height Map 알고리즘

5.1 Height origin

파라미터기본값튜닝 효과
height_origin.modelocal_floor주변 바닥으로 z 기준 추정. odom z jitter에 강하다. odom은 Point-LIO z, fixed는 fixed_z 사용.
fixed_z0.0mode=fixed일 때만 사용.
filter_alpha / max_step0.18 / 0.015클수록 빨리 따라가나 흔들림도 증가. max_step은 frame당 z 기준 최대 변화다.
floor_radius / percentile / min_points0.6 / 0.20 / 20바닥 추정 범위·낮은 값 선택 정도·최소 point. 부족하면 odom z fallback이 가능하다.

5.2 Cell 선택 및 clipping

파라미터기본값튜닝 효과
algorithm.elevation_backendautonomy_min_z낮은 지지 표면을 terrain으로 선택하고 장애물은 별도로 overlay한다.
clipping.enabled / min_z / max_ztrue / 0.0 / 0.48최종 출력 범위. max_z는 HeightMap 거리형 값의 기준 높이이기도 하다.
min_points_per_cell3terrain 최소 지지점. 올리면 노이즈는 감소하고 빈 cell은 증가한다.
supported_min_enabled / support_bandtrue / 0.025낮은 반환점이 이웃 낮은 반환점과 2.5 cm 이내에서 지지되는지 확인한다.
obstacle_override_enabledtrueterrain filtering 뒤에도 장애물 top을 보존한다.
obstacle_min_height / min_points / support_band0.035 / 1 / 0.06낮출수록 작은 장애물에 민감해지고 false positive 가능성이 증가한다.
obstacle_projection_radius_cells0장애물을 이웃 cell로 확장할 반경. 0은 edge 번짐을 줄인다.

6. 보간, 노이즈 제거, 평활화

계열 / 파라미터기본값설명 및 권장 조정
interpolation_max_passes / min_neighbors / max_height_diff4 / 3 / 0.02짧고 평탄한 빈틈 보간. 장애물 잔상·edge 번짐이 있으면 pass를 줄이거나 높이차 한계를 낮춘다.

증상별 첫 조치
지지직거림: min_points_per_cell 또는 min_support_neighbors를 한 단계 올린다. 작은 장애물 반응 지연: obstacle_min_height를 낮춘다. 장애물 잔상: temporal_alpha와 interpolation pass를 줄이고 previous-grid fill이 false인지 확인한다.

8. 장애 진단 체크리스트

증상확인 순서
LiDAR 입력 없음ip addr로 NIC/IP 확인 → livox_* 확인 → internal domain에서 raw topic 확인.
HeightMap이 없음heartbeat → Point-LIO registered/local map → 저장 지도면 relocalization 완료 → height_map_debug.manual_mode로 수신단만 분리 점검.
지도와 위치가 어긋남LiDAR extrinsic과 지도 제작 당시 장착 일치 여부 → localization fitness 확인 → 반복 복도/평면에서는 quality gate를 함부로 완화하지 않는다.
제어 PC가 느림internal/external/global-map domain 분리 → 제어 domain의 PointCloud 점검 → elevation 크기/해상도/publish rate 조정.
수신 값 해석 오류매 메시지의 resolution, x_length, y_length로 shape를 계산한다. data는 raw z가 아니라 0.48-cell_z 계열이다.
운용 완료 기준
외부 domain heartbeat가 ready이고, HeightMap 주기가 기대값에 가깝고, data 길이가 width×height와 같으며, 실제 장애물 위치/방향이 base_link 기준과 일치하면 준비가 완료된 것이다.
